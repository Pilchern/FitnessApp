## Priority 1 — Active Debt

### TD-030: Nutrition calorie/protein targets ignore age, height, and sex

- **Severity:** Medium — fitness-safety/accuracy issue, not a crash or data-loss risk
- **Affected files:** `packages/application/src/modules/profiles/nutrition-target.ts`, `packages/domain/src/modules/profiles/user-profile.ts`, `apps/web/src/features/settings/components/settings-form.tsx`
- **Problem:** `NutritionTargetService.computeNutritionTargets()` computes BMR via Mifflin-St Jeor but the `profiles` table has no age, height, or biological-sex fields, so the formula always substitutes `DEFAULT_HEIGHT_CM = 170`, `DEFAULT_AGE = 30`, and an implicit male `+5` constant — real personalization is limited to the user's latest logged body weight and 3 boolean goal flags. The Settings UI button is labeled "Recompute from my stats," which overstates how personalized the number actually is. This session (2026-08-02) added a `MIN_SAFE_DAILY_CALORIES` (1200 kcal) floor and a `notes[]` disclosure array surfaced in the Settings UI so the estimate is no longer presented as precise/medical, but the underlying inputs are still population defaults, not the user's actual stats.
- **Fix:** Add optional `heightCm`, `ageYears`, and `biologicalSex` fields to the profile (new migration + domain + application + infrastructure mapper + Settings form), and use them in `computeBmr`/the sex-based Mifflin-St Jeor constant when present, falling back to today's defaults (with the disclosure note) when absent. Deliberately deferred this session — it requires a schema migration, and this session avoided applying schema changes to the live Supabase project unsupervised (no user available to confirm/verify a live DB change). Code-complete groundwork (the disclosure/floor logic) is in place; the remaining work is purely additive.
- **Effort:** M
